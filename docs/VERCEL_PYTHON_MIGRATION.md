## Vercel Configuration Issues

### Problem 1: Invalid Runtime Specification

**Initial Attempt:**
```json
{
  "functions": {
    "api/**/*.py": {
      "runtime": "python3.9"
    }
  }
}
```

**Error:** `"Function Runtimes must have a valid version, for example 'now-php@1.0.0'."`

**Solution:** Removed explicit runtime - Vercel auto-detects Python 3.12

### Problem 2: Function Pattern Not Matching

**Initial Attempt:**
```json
{
  "functions": {
    "api/**/*.py": {
      "maxDuration": 60
    }
  }
}
```

**Error:** `"The pattern 'api/**/*.py' defined in 'functions' doesn't match any Serverless Functions."`

**Tried:**
- `"api/index.py"` - Still didn't match
- `"api/**/*.py"` - Pattern too broad

**Solution:** Removed `functions` block entirely - Vercel auto-detects Python files in `/api/` directory

### Problem 3: Rewrite Destination Issues

**Initial Attempt:**
```json
{
  "rewrites": [
    {
      "source": "/api/:path*",
      "destination": "/api/index.py"
    }
  ]
}
```

**Problem:** Requests returned 404 or HTML instead of JSON

**Tried:**
- `/api/index.py` - Didn't work
- `/api/index` - Didn't work
- `/api` - Didn't work

**Solution:** Use `/api/index` (without `.py` extension)

## Function Detection Problems

### Problem 4: Vercel Not Detecting Python Functions

**Symptoms:**
- `/api` returning 404
- Python files visible in "Sources" but not in "Resources"
- Build logs showing only Next.js build, no Python function creation

**Root Causes Identified:**

1. **Next.js Detection Override:**
   - Vercel was detecting Next.js and ignoring Python
   - Solution: Disabled Next.js detection

2. **Module-Level App Variable:**
   - FastAPI app must be at module level for auto-detection
   - Solution: Ensured `app = FastAPI()` is at top level

3. **Custom Handler Function:**
   - Initially used `Mangum` adapter with custom `handler`
   - This interfered with Vercel's auto-detection
   - Solution: Removed `Mangum` and custom handler

4. **Folder Naming:**
   - Tried renaming to `/python-api/` - Made it worse!
   - Vercel ONLY auto-detects functions in `/api/` at root
   - Solution: Keep folder as `/api/` at root level

## Next.js to Vite Migration

### Why We Migrated

Vercel was still detecting Next.js even with Python files, causing:
- Next.js build to run instead of Vite
- Python functions not being created
- Routing conflicts

### Changes Made

1. **Disabled Next.js Detection:**
   - Renamed `next.config.mjs` → `next.config.mjs.bak`
   - Renamed `middleware.ts` → `middleware.ts.bak`
   - Renamed `next-env.d.ts` → `next-env.d.ts.bak`

2. **Updated `vercel.json`:**
   ```json
   {
     "buildCommand": "npm run build",
     "outputDirectory": "dist",
     "framework": null,
     "rewrites": [
       {
         "source": "/api/(.*)",
         "destination": "/api/index"
       },
       {
         "source": "/(.*)",
         "destination": "/index.html"
       }
     ]
   }
   ```

3. **Updated `vite.config.ts`:**
   - Set `build.outDir: "dist"`
   - Added proxy for `/api` to `http://localhost:8000` (dev only)
   - Externalized Next.js modules

4. **Updated `tsconfig.json`:**
   - Removed Next.js-specific plugins
   - Excluded `src/app` directory
   - Excluded Next.js server files

## Final Working Configuration

### 1. Project Structure

```
/
├── api/
│   ├── index.py          # FastAPI app (module-level app variable)
│   ├── pyproject.toml   # Python dependencies
│   └── uv.lock          # Lock file
├── requirements.txt      # Fallback for Vercel
├── vercel.json          # Vercel configuration
├── vite.config.ts       # Vite configuration
└── package.json         # Frontend dependencies
```

### 2. `/api/index.py` - Critical Requirements

**Module-Level App Variable:**
```python
# Must be at module level - Vercel detects this
app = FastAPI()

# CORS middleware
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# API Router with /api prefix
api_router = APIRouter(prefix="/api")
app.include_router(api_router)
```

**Key Points:**
- ✅ `app` variable at module level
- ✅ No custom `handler` function
- ✅ No `Mangum` adapter
- ✅ Routes use `APIRouter` with `/api` prefix
- ✅ Global exception handler for JSON responses

### 3. `/vercel.json` - Final Configuration

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "framework": null,
  "rewrites": [
    {
      "source": "/api/(.*)",
      "destination": "/api/index"
    },
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

**Key Points:**
- ✅ No `functions` block (auto-detection)
- ✅ No explicit `runtime` (auto-detection)
- ✅ Rewrite destination: `/api/index` (no `.py` extension)
- ✅ `framework: null` to prevent Next.js detection
- ✅ Explicit `buildCommand` and `outputDirectory` for Vite

### 4. `/requirements.txt` - Root Level

```
fastapi>=0.104.1
uvicorn>=0.24.0
supabase>=2.0.0
PyJWT>=2.8.0
python-multipart>=0.0.22
pytz>=2023.3
```

**Why at root?**
- Vercel checks root-level `requirements.txt` for Python detection
- Acts as fallback if `pyproject.toml` isn't detected
- Ensures dependencies are installed

### 5. `.vercelignore` - Ensure Inclusion

```
# Explicitly include api/ directory
!api/
```

**Why needed?**
- Ensures `/api` directory is not accidentally ignored
- Vercel needs to see Python files to detect them

## Key Lessons Learned

### ✅ What Works

1. **Folder Name:** Must be exactly `/api/` at root level
2. **Module-Level App:** FastAPI `app` variable must be at module level
3. **No Custom Handler:** Don't use `Mangum` or custom handler functions
4. **No Explicit Runtime:** Let Vercel auto-detect Python version
5. **No Functions Block:** Let Vercel auto-detect Python files
6. **Rewrite Destination:** Use `/api/index` (without `.py`)
7. **Requirements.txt:** Include at root as fallback
8. **Framework Null:** Set `framework: null` to prevent Next.js detection

### ❌ What Doesn't Work

1. **Custom Runtime Spec:** `"runtime": "python3.9"` - Invalid format
2. **Functions Pattern:** `"api/**/*.py"` - Doesn't match
3. **Mangum Adapter:** Interferes with auto-detection
4. **Custom Handler:** Breaks auto-detection
5. **Different Folder Name:** `/python-api/` - Not auto-detected
6. **Next.js Detection:** Conflicts with Python functions
7. **Rewrite to `.py`:** `/api/index.py` - Doesn't work

### 🔍 How Vercel Detects Python Functions

1. **Scans `/api/` directory** at root level
2. **Looks for Python files** (`.py` extension)
3. **Checks for FastAPI app** - looks for `app = FastAPI()` at module level
4. **Reads dependencies** from `requirements.txt` or `pyproject.toml`
5. **Auto-generates serverless function** for each Python file
6. **Uses Python 3.12** by default (latest supported)

### 📝 Debugging Checklist

If Python functions aren't detected:

- [ ] Is `/api/` folder at root level? (not `/src/api/` or `/python-api/`)
- [ ] Is `app = FastAPI()` at module level in `index.py`?
- [ ] Is there a `requirements.txt` at root?
- [ ] Is Next.js detection disabled? (`framework: null` in `vercel.json`)
- [ ] Are Next.js config files renamed/removed?
- [ ] Is `.vercelignore` not excluding `/api/`?
- [ ] Is there no custom `handler` function?
- [ ] Is `Mangum` not being used?

### 🚀 Deployment Verification

After deployment, check:

1. **Vercel Dashboard → Deployment → Resources:**
   - Should see `api/index.py` listed as a serverless function

2. **Vercel Dashboard → Deployment → Logs:**
   - Should see Python function creation logs
   - Should see dependency installation from `requirements.txt`

3. **Test Endpoint:**
   - `GET /api/test` should return JSON (not HTML)
   - `GET /api/` should return health check JSON

## Summary

The key to getting Vercel to recognize Python functions was:

1. **Simplification:** Remove all custom handlers and adapters
2. **Standard Structure:** Use `/api/` folder at root with module-level FastAPI app
3. **No Explicit Config:** Let Vercel auto-detect (no `functions` block, no `runtime`)
4. **Disable Next.js:** Prevent framework detection conflicts
5. **Requirements.txt:** Include at root for dependency detection

The migration required patience and systematic debugging, but the final solution is clean and follows Vercel's conventions.
